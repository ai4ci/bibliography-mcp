# Replace the R interface with an MCP server

## Context

The project was a Java library of bibliographic API clients plus an R package
(`biblioapi`) generated by `r6-generator-maven-plugin`. The R package wrapped
the clients in R-facing classes (`rjavaapi` package: `ApiClient`,
`Repository`, `TopicModelAnalyser`, `CitationAnalyser`) and shipped a 122 MB
fat jar for rJava. The R code was generated rather than hand-written, and both
the generator and the wrapper duplicated the Java API surface.

The users of this functionality are increasingly agents, which integrate over
the Model Context Protocol rather than through R bindings.

## Decision

Delete the R interface entirely: the generated `rPackage/`, the `rjavaapi`
package, the `r6-generator-runtime` dependency and the generator plugin
configuration. Expose the functionality over MCP instead, and salvage the
orchestration logic that lived in `rjavaapi` into a plain-Java package
(`uk.co.terminological.bibliography.mcp`: `BiblioFacade`, `Session`,
`Analysis`, `McpTools`, `McpServer`).

## Rationale

* MCP is the integration path the intended consumers actually use; keeping two
  wrappers meant maintaining two surfaces for one capability set.
* The R wrapper was generated code with a heavy rJava build path (a fat jar
  per build, a package generator running at compile time) for a single
  consumer.
* The logic worth keeping (multi-API search routing, record merging, citation
  graph traversal, analysis) is plain Java once the R types are removed, so
  the migration cost was mostly mechanical.


* R users lose the interface. The plain-Java `BiblioFacade`/`Session` remain
  directly usable from JVM code, and a future R binding could wrap those
  rather than the R-era classes.
* The build no longer produces an R package: it produces a runnable server jar
  instead of a jar for rJava. (It did that by shading until 0.0.11, when the
  packaging became a thin jar beside `lib/` — see
  [issue-022](/design/implementation/issues/issue-022-shaded-jar-cannot-render-citations.md).
  Minimising the artefact mattered for an R package and does not here.)
* End-to-end tests imported `rjavaapi.ApiClient` and were re-pointed at
  `BiblioFacade`.
* `R6`-specific quirks disappeared with the code (e.g. DataFrame-shaped
  results became JSON), which also removed a class of column-name coupling.
